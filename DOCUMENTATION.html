1. Project Overview

This project started as the City of Imus government website and was refactored into a white-label template any Philippine Local Government Unit (LGU) can re-skin by swapping a tenant configuration file — without rewriting the application core.

ItemDetail
FrameworkNext.js 14 (App Router) + TypeScript
StylingTailwind CSS — gov.* (national) + tenant.* (LGU branding)
DatabaseSQLite via Prisma (prisma/dev.db) — swappable to Postgres
AuthenticationAuth.js (NextAuth v5) — email + password credentials
ValidationZod (tenant config + API inputs)
i18nEnglish + Filipino (en / fil)
Not using Supabase. The database is local SQLite. AUTH_SECRET is generated locally in your .env file — it is not stored in any cloud dashboard.

2. What Was Built (Phases 0–6)

Phase 0

Tenant Configuration Layer

Moved all Imus-specific data from lib/constants.ts, lib/forms.ts, and lib/digital-services.ts into config/tenants/imus.config.ts with a Zod schema and loader. New LGUs copy _template.config.ts.

Phase 1

National Design System

Philippine flag colors (gov.*), CSS-variable tenant theming (tenant.*), national header strip, legal footer, Transparency Seal badge, language toggle, accessibility controls, and /transparency hub page.

Phase 2

Database Layer

Prisma + SQLite. Models: User, Submission, SubmissionEvent, Attachment, VerificationToken. Form submissions persist to DB (no more JSON files). Attachments stay on disk under data/submissions/<referenceNo>/.

Phase 3

Auth & RBAC

Auth.js credentials login, JWT role claims, middleware route protection, citizen registration with required email verification, admin seed script, permission matrix and segregation-of-duties in lib/rbac.ts.

Phase 4

Citizen Console

/citizen/dashboard — list applications, view detail with timeline and attachments, respond to NEEDS_INFO requests with reply text and document uploads.

Phase 5

Staff Console

/staff/queue — office-scoped processing queue grouped by status. Actions: start review, request info, approve, reject, mark ready, mark released. All enforced server-side.

Phase 6

Admin Console

/admin — user management (create staff/admin, assign offices, toggle permissions), all-submissions view with filters, read-only offices and tenant content views.

4. First-Time Setup (Highlighted Steps)

Run these steps after cloning from GitHub. The database and .env are not included in the repository.

⚠ Avoid OneDrive folders. Cloning to OneDrive\Desktop\... can cause EPERM errors during prisma generate. Prefer C:\dev\city-of-imus or similar.
  1. Clone the repository 
    git clone https://github.com/AceDagalea/city-of-imus.git
cd city-of-imus
  2. Install dependencies

    Also runs prisma generate automatically via the postinstall script.

    npm install
  3. Create the environment file 
    # Windows PowerShell
Copy-Item .env.local.example .env

# macOS / Linux
cp .env.local.example .env
  4. Generate AUTH_SECRET and paste into .env 
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

    Replace AUTH_SECRET="replace-me" with the generated value. Do not commit .env.

  5. Create database tables and seed the admin account 
    npm run db:setup

    Equivalent to npx prisma migrate deploy + npx prisma db seed.

  6. Start the development server 
    npm run dev

    Open http://localhost:3000

  7. Log in or register

    Admin: /login with seeded credentials (see Section 7). Citizens: /register — verification link prints in the terminal.

✓ Success checklist: npm run dev starts without errors · /login loads · Admin login works · npx prisma studio shows the User table

5. Environment Variables

All variables live in .env at the project root (copy from .env.local.example).

VariableExampleDescription
TENANT imus Selects config/tenants/<TENANT>.config.ts. Defaults to imus.
DATABASE_URL "file:./dev.db" SQLite path relative to prisma/. For Postgres, change provider in schema and set a Postgres URL.
AUTH_SECRET "a1b2c3..." Required. Random hex string for Auth.js JWT signing. Generate locally — not from Supabase or GitHub.
SEED_ADMIN_EMAIL admin@imus.gov.ph Optional override for seed script (default: admin@imus.gov.ph).
SEED_ADMIN_PASSWORD ChangeMe@2026 Optional override for seed script password.

8. Request Lifecycle

DRAFT → SUBMITTED → UNDER_REVIEW ⇄ NEEDS_INFO
                              ↓
                    APPROVED → READY_FOR_RELEASE → RELEASED
                              ↓
                           REJECTED
  • Only verified citizens can submit requests.
  • Staff see only submissions for their assigned offices.
  • Segregation of duties: the staff member who moves a submission to UNDER_REVIEW cannot also approve it — a different approver must decide.
  • Every status change writes a SubmissionEvent row (audit trail).
